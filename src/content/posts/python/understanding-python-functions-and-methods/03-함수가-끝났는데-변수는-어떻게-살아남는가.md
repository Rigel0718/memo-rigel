앞선 글에서는 Python에서 함수 내부의 이름을 LEGB 규칙에 따라 탐색한다는 사실을 살펴봤다.

그런데 다음 코드를 보자.

```python
def outer():
    x = 10

    def inner():
        return x

    return inner


inner = outer()
print(inner())  # 10
```

`inner`는 `outer`에서 정의한 변수 `x`를 참조한다.

여기서 이상한 점이 하나 있다. `inner()`가 호출되는 시점에는 이미 `outer()`의 실행이 종료되었다는 것이다.

함수가 호출되면 실행을 위한 Frame이 생성되고, 실행을 마치면 해당 Frame도 더 이상 유지될 필요가 없다.

그렇다면 `outer()`의 실행이 종료되었는데도 `inner()`는 어떻게 `x`를 참조할 수 있을까?

이 질문을 이해하려면 **Closure**라는 개념을 알아야 한다.

## 1. Closure란 무엇인가?

Closure는 **함수가 자신이 정의된 외부 Lexical Scope의 변수 바인딩을 캡처하여, 이후에도 해당 변수에 접근할 수 있도록 하는 개념**이다.

쉽게 말해, 함수가 자신이 정의된 외부 환경의 필요한 변수를 기억하는 것이다.

Python에서는 이렇게 외부 변수의 바인딩을 캡처한 함수를 Closure라고 부른다. 별도의 `Closure` 타입이 존재하는 것은 아니며, 여전히 Function Object다.

앞선 예제를 다시 보자.

```python
def outer():
    x = 10

    def inner():
        return x

    return inner
```

`inner`는 `x`를 자신의 Local Scope에서 정의하지 않았다. 대신 자신을 감싸는 `outer`의 Scope에서 참조한다.

Python 공식 문서에서는 이처럼 함수 내부에서 사용하지만 해당 Scope의 Local Variable은 아닌 변수를 **Free Variable**이라고 한다.

이 중 외부 Scope에 정의된 바인딩을 참조하는 변수를 **Closure Variable**이라고 한다. Global이나 Builtin Namespace에서 탐색되는 이름과는 구분된다.

위 코드의 `x`는 `outer` 입장에서는 Local Variable이지만, `inner` 입장에서는 Closure Variable이다.

여기서 중요한 점은 `inner`가 어디에서 호출되는지가 아니라, **어디에서 정의되었는지**를 기준으로 외부 변수를 참조한다는 것이다.

그리고 Closure는 이러한 외부 변수의 바인딩을 함수와 함께 유지한다.

그렇다면 외부 함수가 종료된 이후에도 이 바인딩을 어떻게 유지할까?

## 2. 외부 함수가 종료되어도 변수가 남아 있는 이유

Closure가 외부 변수를 기억한다고 해서 함수가 생성되는 순간의 값을 단순히 복사해 두는 것은 아니다.

다음 코드를 살펴보자.

```python
def outer():
    x = 10

    def inner():
        return x

    x = 20
    return inner


inner = outer()
print(inner())  # 20
```

`inner`가 생성되었을 때 `x`는 `10`이었다.

하지만 `inner`를 반환하기 전에 `x`를 `20`에 다시 바인딩하면, 이후 `inner()`는 `20`을 반환한다.

즉, `inner`는 생성 당시의 값 `10`을 복사한 것이 아니라 **외부 변수** `x`**의 바인딩을 참조하고 있는 것**이다.

CPython은 이러한 바인딩을 유지하기 위해 **Cell Object**를 사용한다.

Cell Object는 객체에 대한 참조를 보관하는 객체로, 함수가 외부 변수의 현재 바인딩에 접근할 수 있도록 한다.

실제로 확인해 보자.

```python
def outer():
    x = 10

    def inner():
        return x

    print(inner.__closure__)
    print(inner.__closure__[0].cell_contents)

    return inner


inner = outer()
```

출력은 대략 다음과 같다.

```
(<cell at 0x...: int object at 0x...>,)
10
```

`inner.__closure__`는 Closure Variable의 바인딩을 유지하는 Cell Object들이 담긴 Tuple이다.

`cell_contents`는 해당 Cell이 참조하는 객체를 보여준다.

이를 단순화하면 다음과 같다.

```
inner (Function Object)
    │
    └── __closure__
            │
            └── Tuple
                  │
                  └── Cell Object
                         │
                         └── int Object (10)
```

여기서 주의할 점은 **Closure라는 개념과** `__closure__`**라는 속성은 다르다**는 것이다.

Closure는 함수가 외부 변수의 바인딩을 캡처하는 개념이고, `__closure__`는 CPython에서 이를 구현하는 Cell Object들에 접근할 수 있는 Function Object의 속성이다.

따라서 `outer()`가 종료되더라도 반환된 `inner` Function Object가 해당 Cell을 참조하고 있다면 외부 변수의 바인딩은 계속 유지된다.

반드시 `outer()`의 Frame 전체를 보존해야 하는 것은 아니다.

## 3. Closure는 어디에 사용할까?

Closure는 외부 함수가 정의한 설정값이나 상태를 내부 함수에서 계속 활용해야 할 때 유용하다.

예를 들어 다음과 같이 특정 비율을 적용하는 함수를 만들 수 있다.

```python
def make_multiplier(factor):
    def multiply(value):
        return value * factor

    return multiply


double = make_multiplier(2)
triple = make_multiplier(3)

print(double(10))  # 20
print(triple(10))  # 30
```

`make_multiplier()`는 전달받은 `factor`를 사용하는 내부 함수를 반환한다.

`double`은 `factor`가 `2`인 바인딩을, `triple`은 `factor`가 `3`인 바인딩을 각각 유지한다.

따라서 `make_multiplier()`의 실행이 종료된 이후에도 각 함수는 서로 다른 설정값을 사용할 수 있다.

이처럼 Closure는 함수마다 별도의 설정값이나 상태를 유지해야 할 때 활용된다.

대표적으로 Decorator, Callback, Function Factory 등에서 이러한 특성을 찾아볼 수 있다.

특히 다음 글에서 다룰 **Decorator**는 함수를 감싸는 새로운 함수를 정의하고 반환하는 경우가 많다. 이때 내부 함수가 외부 함수의 변수나 전달받은 Function Object를 참조하는 데 Closure가 활용된다.

## 4. 마무리

처음 질문으로 돌아가 보자.

> 함수의 실행이 종료되었는데도 외부 변수를 어떻게 참조할 수 있을까?

핵심은 함수의 실행이 끝나는 것과 해당 함수에서 만들어진 객체 및 변수 바인딩의 생명주기가 반드시 같지는 않다는 것이다.

Closure를 이용하면 함수는 자신이 정의된 외부 Scope의 필요한 변수 바인딩을 계속 참조할 수 있다.

CPython에서는 이러한 바인딩을 Cell Object로 관리하고, Function Object의 `__closure__` 속성을 통해 확인할 수 있다.

따라서 외부 함수의 실행이 종료되더라도 내부 함수가 필요한 바인딩을 유지하고 있다면 해당 변수에 계속 접근할 수 있다.

이러한 원리를 이해했다면 다음 글에서 다룰 Decorator가 어떻게 함수를 감싸고, 원래 Function Object를 기억하는지도 더 쉽게 이해할 수 있을 것이다.
