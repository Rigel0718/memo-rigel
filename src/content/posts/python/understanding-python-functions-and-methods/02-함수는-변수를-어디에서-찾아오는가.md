앞선 글에서는 Python에서 `def`가 실행되면 Function Object가 생성되고, 해당 객체가 이름에 바인딩된다는 사실을 살펴봤다.

그렇다면 함수 내부에서 사용하는 이름은 어떻게 결정될까?

```python
x = 10

def foo():
    x = 20
    print(x)

foo()     # 20
print(x)  # 10
```

두 곳에서 동일한 `x`라는 이름을 사용했지만, 서로 다른 값이 출력된다.

함수 내부의 `x`와 함수 외부의 `x`가 서로 다른 객체에 바인딩되어 있기 때문이다.

그런데 다음과 같이 함수 내부의 `x = 20`을 제거하면 어떻게 될까?

```python
x = 10

def foo():
    print(x)

foo()  # 10
```

이번에는 함수 내부에서 정의하지 않은 `x`를 정상적으로 참조한다.

Python은 어떤 경우에는 함수 내부의 이름을 사용하고, 어떤 경우에는 함수 바깥의 이름을 찾아온다.

이러한 동작을 이해하려면 먼저 **Namespace와 Scope**, 그리고 Python의 이름 탐색 규칙인 **LEGB**를 알아야 한다.

## 1. Namespace와 Scope는 무엇이 다를까?

Python에서 변수는 값을 직접 담는 상자라기보다 객체에 연결된 이름이다.

예를 들어 다음 코드는 `x`라는 이름을 정수 객체 `10`에 바인딩한다.

```python
x = 10
```

그렇다면 이러한 이름과 객체의 바인딩은 어디에서 관리될까?

### Namespace — 이름과 객체의 바인딩을 관리하는 공간

Namespace는 이름과 객체 사이의 바인딩을 관리하는 공간이다.

Python 프로그램에는 여러 Namespace가 존재할 수 있다. 대표적으로 모듈의 Global Namespace와 함수 호출 시 사용하는 Local Namespace가 있다.

```python
x = 10

def foo():
    y = 20
    print(y)
```

이 코드에서 모듈의 Global Namespace에는 `x`와 `foo`라는 이름이 존재한다.

`foo()`가 호출되면 해당 함수의 지역 이름을 관리하는 Local Namespace를 사용하게 된다. 함수 내부의 `y`는 여기에 바인딩된다.

개념적으로 표현하면 다음과 같다.

```text
Global Namespace
  ├── x   → 10
  └── foo → Function Object

foo() 호출 시
  └── Local Namespace
        └── y → 20
```

여기서 Namespace는 반드시 하나의 Dictionary 객체로 구현된다는 의미는 아니다.

예를 들어 모듈의 Global Namespace는 일반적으로 Dictionary로 관리되지만, CPython의 함수 지역 변수는 실행 효율을 위해 다른 내부 표현을 사용할 수 있다.

중요한 것은 Namespace가 **이름과 객체의 대응 관계를 관리한다는 개념**이라는 점이다.

### Scope — 이름을 참조할 수 있는 범위

Namespace가 이름의 바인딩을 관리한다면, Scope는 코드의 특정 위치에서 어떤 이름을 참조할 수 있는지를 결정한다.

앞서 살펴본 코드를 다시 보자.

```python
x = 10

def foo():
    print(x)

foo()  # 10
```

`foo()` 내부에는 `x`가 정의되어 있지 않다.

그런데도 `print(x)`가 정상적으로 동작하는 이유는 함수 내부에서 Global Scope의 이름을 참조할 수 있기 때문이다.

즉, 두 개념은 다음과 같이 구분할 수 있다.

- **Namespace**: 이름과 객체의 바인딩을 관리하는 공간
- **Scope**: 코드에서 이름을 참조할 수 있는 범위

Namespace가 이름을 관리하는 구조에 관한 개념이라면, Scope는 해당 이름의 가시성과 탐색 규칙에 관한 개념이다.

## 2. Local과 Global — 같은 이름이 존재하면 어떻게 될까?

이제 함수 내부와 외부에 동일한 이름이 존재하는 상황을 살펴보자.

```python
x = 10

def foo():
    x = 20
    print(x)

foo()     # 20
print(x)  # 10
```

모듈 수준에서 바인딩된 `x`는 Global Scope에 속한다.

반면 `foo()` 내부의 `x = 20`은 해당 함수의 Local Scope에 속하는 이름을 바인딩한다.

따라서 함수 내부의 `print(x)`는 지역 변수 `x`를 참조하고, 함수 바깥의 `print(x)`는 전역 변수 `x`를 참조한다.

여기서 중요한 것은 Python이 함수 내부의 이름을 어떻게 지역 변수로 판단하는가이다.

### 지역 변수는 언제 결정될까?

다음 코드를 살펴보자.

```python
x = 10

def foo():
    print(x)
    x = 20

foo()
```

앞에서 배운 내용만 생각하면 `print(x)`가 먼저 실행되므로 Global의 `x = 10`을 참조할 것 같기도 하다.

하지만 실제로는 다음 오류가 발생한다.

```text
UnboundLocalError: cannot access local variable 'x' where it is not associated with a value
```

왜 이런 일이 발생할까?

Python은 함수를 컴파일할 때 함수 본문의 이름 바인딩을 분석한다.

이 과정에서 `global`이나 `nonlocal` 선언 없이 함수 내부에 `x = 20`이라는 대입문이 존재하면, `x`를 해당 함수의 지역 변수로 판단한다.

이러한 판단은 단순히 코드가 실행되는 순서에 따라 이루어지는 것이 아니다. **함수 본문 전체의 바인딩을 분석한 결과**다.

따라서 앞선 코드는 다음과 같이 동작한다.

1. 컴파일 시점에 `x`가 `foo`의 Local 변수로 분류된다.
2. `foo()`가 호출되고 `print(x)`가 실행된다.
3. 하지만 Local의 `x`에는 아직 값이 바인딩되지 않았다.
4. 결과적으로 `UnboundLocalError`가 발생한다.

여기서 중요한 사실을 알 수 있다.

**Local로 분류된 이름에 아직 값이 없다고 해서 Python이 자동으로 Global에서 같은 이름을 찾아오는 것은 아니다.**

이름을 어느 Scope에서 참조할 것인지 결정하는 과정과, 실제 실행 시점에 해당 이름에 값이 바인딩되어 있는지는 구분해야 한다.

### `global` — 전역 이름에 바인딩하려면?

함수 내부에서 전역 변수 `x`를 변경하고 싶다면 어떻게 해야 할까?

이때 사용하는 것이 `global` 선언이다.

```python
x = 10

def foo():
    global x
    print(x)
    x = 20

foo()     # 10
print(x)  # 20
```

`global x`는 함수 내부의 `x`가 Local이 아니라 모듈의 Global 이름을 사용하도록 선언한다.

따라서 `foo()`의 `x = 20`은 새로운 지역 바인딩을 만드는 대신 Global의 `x`를 변경한다.

`global`은 새로운 값을 복사하거나 자동으로 전역 변수를 생성하는 명령이 아니다. **함수 내부에서 특정 이름의 Scope를 지정하는 선언**이다.

또한 전역 이름이 미리 존재하지 않더라도 `global`을 선언하고 값을 바인딩할 수 있다.

## 3. Enclosing — 중첩 함수는 이름을 어디에서 찾을까?

지금까지는 Local과 Global만 살펴봤다.

그런데 Python에서는 함수 내부에 또 다른 함수를 정의할 수 있다.

```python
x = 10

def outer():
    x = 20

    def inner():
        print(x)

    inner()

outer()  # 20
```

이 코드에서 `inner()`에는 `x`를 바인딩하는 문장이 없다.

그렇다면 Global의 `x = 10`을 참조해야 할까?

그렇지 않다.

`inner()`는 자신을 감싸는 `outer()`의 Scope에서 `x`를 찾아 `20`을 출력한다.

이처럼 **중첩 함수에서 바깥쪽 함수의 Scope를 Enclosing Scope**라고 부른다.

여기서 중요한 것은 Enclosing Scope가 단순히 함수를 호출한 위치로 결정되는 것이 아니라는 점이다.

Python의 일반적인 함수 이름 탐색은 함수가 코드상 어디에서 정의되었는지에 기반한다. 이러한 특성을 Lexical Scoping이라고 한다.

### Enclosing Scope의 이름도 변경할 수 있을까?

앞에서는 `inner()`에서 `outer()`의 `x`를 참조했다.

그렇다면 이번에는 값을 변경해 보자.

```python
def outer():
    x = 10

    def inner():
        x = 20

    inner()
    print(x)

outer()  # 10
```

`inner()`에서 `x = 20`을 실행했지만 `outer()`의 `x`는 변경되지 않았다.

이유는 앞서 살펴본 Local 변수의 규칙과 같다.

`inner()` 내부의 대입문은 기본적으로 해당 함수의 지역 이름을 바인딩한다.

따라서 `outer()`의 `x`와 `inner()`의 `x`는 서로 다른 바인딩이다.

### `nonlocal` — 바깥 함수의 이름에 바인딩하려면?

Enclosing Scope에 존재하는 이름을 변경하려면 `nonlocal`을 사용할 수 있다.

```python
def outer():
    x = 10

    def inner():
        nonlocal x
        x = 20

    inner()
    print(x)

outer()  # 20
```

`nonlocal x`는 `inner()`의 `x`가 현재 함수의 Local이 아니라, 바깥 함수 Scope에 이미 존재하는 바인딩을 사용하도록 선언한다.

따라서 `x = 20`은 `outer()`의 `x`에 새로운 값을 바인딩한다.

여기서 `global`과 `nonlocal`은 비슷해 보이지만 중요한 차이가 있다.

| 구분 | `global` | `nonlocal` |
|---|---|---|
| 참조 대상 | 모듈의 Global Scope | 바깥 함수의 Enclosing Scope |
| 중첩 함수 필요 여부 | 필요 없음 | 해당 이름의 바깥 함수 바인딩 필요 |
| 기존 바인딩 | 없어도 선언 가능 | 반드시 존재해야 함 |
| 주요 용도 | 전역 이름에 바인딩 | 바깥 함수의 이름에 재바인딩 |

특히 `nonlocal`은 Global을 대신하는 선언이 아니다.

```python
x = 10

def foo():
    nonlocal x
    x = 20
```

이 코드는 `SyntaxError`를 발생시킨다.

`foo()`를 감싸는 함수 Scope에 `x`라는 바인딩이 없기 때문이다. Global에 `x`가 존재하더라도 `nonlocal`의 대상이 되지는 않는다.

또한 Enclosing 함수가 여러 단계라면, `nonlocal`은 해당 이름이 바인딩된 가장 가까운 바깥 함수 Scope를 사용한다.

여기까지 살펴보면 Python에서는 **이름을 참조하는 것과 이름에 값을 바인딩하는 것이 서로 다른 규칙을 따른다**는 사실을 알 수 있다.

## 4. LEGB — Python은 이름을 어떤 순서로 찾을까?

이제 지금까지 배운 Local, Enclosing, Global을 하나로 연결해 보자.

여기에 Python이 기본으로 제공하는 Built-in Scope까지 더하면 일반적인 함수의 이름 탐색 규칙인 **LEGB**가 완성된다.

| 순서 | Scope | 의미 |
|---|---|---|
| L | Local | 현재 함수의 지역 Scope |
| E | Enclosing | 바깥쪽 함수들의 Scope |
| G | Global | 현재 모듈의 전역 Scope |
| B | Built-in | Python이 기본으로 제공하는 이름의 Scope |

### Built-in Scope는 무엇일까?

Python에서는 직접 정의하지 않아도 사용할 수 있는 함수들이 있다.

```python
def foo():
    print(len([1, 2, 3]))

foo()  # 3
```

`foo()` 내부에는 `print`나 `len`이라는 이름을 바인딩한 적이 없다.

그런데도 이 함수들을 호출할 수 있는 이유는 Python이 Built-in Namespace에서 해당 이름들을 찾을 수 있기 때문이다.

내장 함수라고 해서 언제나 다른 Scope보다 우선하는 것은 아니다.

```python
len = 100

def foo():
    print(len)

foo()  # 100
```

여기서는 Global에 `len`이라는 이름이 존재한다.

따라서 `foo()`는 Built-in의 `len()` 함수까지 탐색하지 않고 Global의 `len`을 참조한다.

이처럼 바깥쪽 Scope의 이름이 안쪽 Scope의 동일한 이름에 의해 가려지는 현상을 Name Shadowing이라고 한다.

### LEGB를 하나의 예제로 살펴보자

```python
x = "Global"

def outer():
    x = "Enclosing"

    def inner():
        x = "Local"
        print(x)

    inner()

outer()  # Local
```

`inner()`에서 사용한 `x`는 해당 함수의 Local 변수다.

이미 `x = "Local"`을 통해 값이 바인딩되어 있으므로 Enclosing이나 Global의 `x`를 사용할 필요가 없다.

그렇다면 `inner()`의 `x = "Local"`을 제거하면 어떻게 될까?

이번에는 `outer()`의 Enclosing Scope에서 `x`를 참조하므로 `"Enclosing"`이 출력된다.

여기서 `outer()`의 `x`까지 제거하면 Global의 `"Global"`을 참조하게 된다.

이처럼 LEGB는 Python의 이름 탐색에서 어느 Scope의 바인딩이 사용되는지 이해하기 위한 기본 규칙이다.

하지만 한 가지 주의해야 한다.

**LEGB는 이름을 사용할 때마다 무조건 Local부터 Built-in까지 순차적으로 검색한다는 의미는 아니다.**

앞에서 살펴본 `UnboundLocalError`가 대표적인 사례다.

```python
x = 10

def foo():
    print(x)
    x = 20

foo()
```

Python은 함수 본문을 분석하여 `x`를 Local 변수로 분류한다. 따라서 실행 시 해당 지역 변수가 아직 바인딩되지 않았다면 Global의 `x`로 넘어가지 않고 오류를 발생시킨다.

즉, 실제 이름 해석에는 컴파일 시점의 Scope 분석과 실행 시점의 바인딩 상태가 함께 작용한다.

또한 클래스 본문과 같은 일부 코드 블록에는 별도의 이름 해석 규칙이 존재한다. 여기서 설명한 LEGB는 일반적인 함수와 중첩 함수를 이해하기 위한 기본 모델이다.

## 마무리

Python에서 함수 내부의 이름은 단순히 코드에 등장한 위치만으로 결정되지 않는다.

Namespace는 이름과 객체의 바인딩을 관리하고, Scope는 코드에서 어떤 이름을 참조할 수 있는지를 결정한다.

일반적인 함수에서는 Local, Enclosing, Global, Built-in으로 이어지는 LEGB 규칙을 통해 이름 탐색을 이해할 수 있다.

다만 이름을 참조하는 것과 이름에 바인딩하는 것은 구분해야 한다.

함수 내부의 대입문은 기본적으로 지역 이름을 바인딩하며, `global`과 `nonlocal`은 이러한 바인딩의 대상을 명시적으로 변경한다. 또한 Python은 컴파일 과정에서 지역 이름을 분석하므로, 단순히 실행 순서에 따라 외부 Scope를 검색하는 것은 아니다.

결국 **함수에서 어떤 이름을 사용할 수 있는지 이해하려면, 이름의 바인딩이 어디에 속하는지와 해당 코드를 감싸는 Scope가 무엇인지를 함께 살펴봐야 한다.**

이러한 이름 탐색 규칙은 이후 Closure를 이해하는 기초가 된다.

Closure에서는 바깥 함수의 실행이 끝난 이후에도 내부 함수가 Enclosing Scope의 변수를 어떻게 참조할 수 있는지 살펴볼 것이다.
